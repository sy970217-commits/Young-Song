# 넘겨 PRD (제품 요구사항 문서)

> 기준: 저장소의 `명세.md`(현재 구현 기준)와 사업계획서 「넘겨」. 현재 구현은 **MVP 시제품**이고, 계획서의 목표 중 일부는 아직 없다. 구현된 것과 앞으로 할 것을 구분해서 적었다.
> 관련 문서: [화면 설계서](화면설계서.md) · [ERD](ERD.md) · [API 명세서](API명세서.md)

## 1. 한눈에 보기

| 항목 | 내용 |
| --- | --- |
| 서비스명 | 넘겨 (화면 이름: 양도권 넘기기) |
| 한 문장 | 못 쓰게 된 예약·이용권을, 시간 안에, 사기 걱정 없이 넘긴다 |
| 첫 시장 | 제주 지역 영화 좌석 예매 양도 (CGV·롯데시네마·메가박스 7개 극장) |
| 첫 고객 | 당일·임박 영화 예매를 못 쓰게 된 제주 거주 20~40대 |
| 수익모델 | 수수료 0원, 업체 광고 + 제휴 매출 (계획) |
| 현재 단계 | 노코드에 가까운 웹 시제품 (정적 페이지 + Supabase + Vercel) |

## 2. 배경과 문제

중고거래 앱에서 영화 좌석을 팔고 있지만, 양도 전용 기능이 없어 아래 손실이 난다 (사업계획서 1장, 당근 양도 글 8건 분석).

| 문제 | 설명 | 이 제품의 대응 |
| --- | --- | --- |
| 시간 손실 | 게시순 피드에 묻혀 구매자가 찾기 전에 상영이 시작된다 | **상영 임박순 정렬**, 상영이 지나면 자동 숨김·삭제 |
| 가격 손실 | 정가의 약 24% 수준으로 팔린다 | 정가 이하(16,000원)만 등록, 500원 단위 가격 조절 |
| 정보 비대칭 | 극장·시간·리클라이너 여부가 글마다 제각각이다 | **표준 양식**(영화·극장·상영일·시간·가격·리클라이너) |
| 신뢰 문제 | 거래를 보증할 장치가 없다 | 판매 상태 표시, 로그인한 글쓴이만 수정·삭제 (결제·에스크로는 미구현) |

## 3. 목표와 지표

| 구분 | 목표 | 측정 방법 | 현재 |
| --- | --- | --- | --- |
| 거래 성사율 | 등록 대비 판매 완료 50% | `tickets.status = '판매 완료'` 비율 | 지표 화면 없음 (SQL로 집계 가능) |
| 상영 전 판매 완료 비율 | 높을수록 좋음 | 삭제 전 `status` 기록 필요 | 자동 삭제 때문에 이력이 사라짐 → 개선 필요 |
| 등록 수 | 3개월 100건 | `count(tickets)` | - |
| 재이용률 | 30% | 같은 `user_id`의 재등록 | - |

> 자동 삭제가 글을 지우므로 성사율·재이용률을 보려면 **삭제 전에 집계를 남기는 장치**가 필요하다 (6장 미결 사항).

## 4. 사용자

| 역할 | 설명 | 할 수 있는 일 |
| --- | --- | --- |
| 방문자(구매자) | 로그인하지 않은 사람 | 목록 보기, 줄을 눌러 판매 링크로 이동, 전화 걸기, 이미지 보기, 화면 색 바꾸기 |
| 판매자(로그인 사용자) | 아이디(숫자 11자리)로 가입·로그인한 사람 | 위 전부 + 양도권 등록, **내 글만** 판매 상태 변경·이미지 추가/변경/삭제·글 삭제 |
| 시스템(자동 작업) | Vercel Cron | 하루 지난 글과 이미지 자동 삭제 |

대표 인물
- **판매자 지수 (30대, 제주시)**: 쿠폰으로 예매했지만 못 가게 됐다. 1분 안에 올리고 싶다.
- **구매자 민수 (20대, 대학생)**: 오늘 저녁 영화를 싸게 보고 싶다. 임박한 순서로 보고 바로 연락하고 싶다.

## 5. 범위

### 5-1. 지금 구현된 것 (In scope)

| ID | 기능 | 우선순위 | 수용 기준 |
| --- | --- | --- | --- |
| F-01 | 가입·로그인·로그아웃 | 필수 | 숫자 11자리 아이디 + 8자 이상 비밀번호로 가입, 새로고침해도 로그인 유지, 이메일 로그인 없음 |
| F-02 | 양도권 등록 | 필수 | 영화제목·극장(7곳)·가격·상영일 필수, 상영시간·리클라이너 선택, 지난 상영은 등록 불가 |
| F-03 | 가격 규칙 | 필수 | 0~16,000원, −500/+500 버튼, 서버(DB)에서도 16,000원 초과 거절 |
| F-04 | 연락 방법(판매링크 또는 전화번호 중 하나) | 필수 | 판매링크는 `daangn` 주소만, 전화번호는 숫자와 `-`만 9~11자리 |
| F-05 | 목록 보기 | 필수 | 누구나 읽기, 한 줄 형식 `영화 극장 상영일 상영시간 가격 리클라이너` |
| F-06 | 상영 임박순 정렬·자동 숨김 | 필수 | 가까운 상영이 위, 판매 완료는 아래, 상영 시각 지난 글은 안 보임 (한국 시간, 1분마다 갱신) |
| F-07 | 판매 상태 | 필수 | 내 글에서 판매 중 → 예약 중 → 판매 완료 순환, 판매 중 개수 표시 |
| F-08 | 줄 눌러 판매 링크 이동, 전화 걸기 | 필수 | 링크 있으면 새 창, 전화번호 있으면 `전화` 버튼으로 전화 앱 열기 |
| F-09 | 이미지 첨부 | 선택 | 글당 1장, 5MB 이하 이미지, 미리보기, 바꾸기·지우기, 저장소 파일도 함께 삭제 |
| F-10 | 내 글만 수정·삭제 | 필수 | 남의 글에는 버튼이 없고, 서버 권한 규칙(RLS)도 막음 |
| F-11 | 하루 지난 글 자동 삭제 | 필수 | 상영일 다음 날(한국 0시)부터 대상, 이미지 포함 삭제, 암호 없는 호출은 거절 |
| F-12 | 다크 모드 | 선택 | 버튼으로 전환, 새로고침해도 유지 |
| F-13 | 한국 시간 기준 날짜·시각 | 필수 | 기기 시간대와 무관, 날이 바뀌면 오늘·내일 표기와 기본값 갱신 |

### 5-2. 하지 않는 것 / 아직 없는 것 (Out of scope)

사업계획서 MVP ②③④와 지표 항목이 아직 없다.

| 항목 | 상태 | 비고 |
| --- | --- | --- |
| 임박 알림 구독 (MVP ②) | 미구현 | 극장·시간대별 알림, 카카오 채널·웹 푸시 후보 |
| 결제 후 예매번호 공개·에스크로 (MVP ③) | 미구현 | 지금은 판매자에게 직접 연락하는 방식 |
| 거래 후 상호 평가·신고 (MVP ④) | 미구현 | |
| 극장·시간·인원 필터, 좌석·인원·발권 방법 정보 | 미구현 | 계획서 문제 3 대응 |
| 상영작 영화제목 목록(TMDB, 매일 갱신) | 제안만 있음 | 사용자 확인 대기 중 |
| 관리자 지표 화면, 광고 배너 자리 | 미구현 | 계획서 3-6 |

| 공연·숙박·렌터카 등 다른 카테고리 | 계획 | 2차 시장 |

## 6. 정책과 규칙

| 규칙 | 내용 | 적용 위치 |
| --- | --- | --- |
| 정가 이하만 | 가격 16,000원 이하 (암표 방지, 계획서 2-5) | 화면 + DB check 제약 |
| 한국 시간 | 모든 날짜·시각은 `Asia/Seoul` 기준 | 화면 + 자동 삭제 |
| 상영 지나면 숨김 | 상영 시각(없으면 그날 23:59)이 지나면 목록에서 제외 | 화면 (1분마다) |
| 하루 지나면 삭제 | 상영일 < 오늘(한국)인 글, 상영일이 없는 글은 올린 지 24시간 | 자동 삭제 작업 |
| 내 글만 수정·삭제 | `user_id = auth.uid()` | RLS |
| 이미지 | 이미지 형식만, 5MB 이하, 글당 1장 | 화면 + 저장소 버킷 설정 |
| 연락 방법 | 둘 중 하나만 저장 (다른 쪽은 비움) | 화면 |
| 비밀 키 | `SUPABASE_SECRET_KEY`는 Vercel 환경 변수에만 둔다 | 배포 |

## 7. 비기능 요구사항

| 항목 | 기준 |
| --- | --- |
| 화면 | 휴대폰 폭(375px)에서 가로 스크롤 없이 사용, 큰 터치 버튼 |
| 호환 | 최신 모바일·데스크톱 브라우저, 외부 라이브러리(CDN) 사용 안 함 |
| 보안 | 공개 키만 브라우저에 둔다, 글 수정·삭제는 RLS로 서버가 막는다, 자동 삭제는 암호(`CRON_SECRET`) 필요, 링크는 `http(s)`만 열고 `javascript:` 등은 거절 |
| 개인정보 | 전화번호가 로그아웃한 사람에게도 보인다 (미결 사항) |
| 성능 | 목록은 한 번에 전체를 읽는다 (수백 건까지 가정), 이후 페이지 나누기 필요 |
| 가용성 | Supabase·Vercel 무료 요금제 한도 안에서 운영 |

## 8. 의존 서비스와 설정

| 서비스 | 쓰임 | 필요한 설정 (직접 해야 함) |
| --- | --- | --- |
| Supabase Database | `tickets` 표, RLS | SQL 실행 ([ERD](ERD.md)) |
| Supabase Auth | 아이디·비밀번호 로그인 | 현재는 **Phone 사용 + Confirm phone 끔**이 필요. Email 방식으로 바꾸면 Email 사용 + Confirm email 끔 |
| Supabase Storage | 이미지 버킷 `images` (공개, 5MB, 이미지 형식) | 버킷·정책 SQL |
| Vercel | 호스팅, 하루 한 번 Cron | `SUPABASE_SECRET_KEY`, `CRON_SECRET` 환경 변수 |

## 9. 미결 사항과 리스크

| 번호 | 내용 | 영향 | 제안 |
| --- | --- | --- | --- |
| Q1 | 로그인이 속으로 Supabase Phone 방식을 써서 **Phone 설정이 꺼져 있으면 로그인·가입이 안 된다** | 높음 | 아이디를 가짜 이메일로 바꿔 Email 방식 사용 ("B안") |
| Q2 | 전화번호가 모두에게 공개된다 | 높음 | 로그인한 사람에게만 보이기 또는 예약 확정 뒤 공개 |
| Q3 | 판매 링크를 `daangn` 주소로만 받는다. 계획서 3-5는 "중고거래 앱 안에서 외부 앱 유도는 운영정책상 제한될 수 있다"고 적었다 | 중간 | 번개장터·중고나라 등으로 넓힐지, 링크를 선택으로 할지 결정 |
| Q4 | 자동 삭제로 거래 이력(성사율)이 사라진다 | 중간 | 삭제 전에 일별 집계 표에 남기기 |
| Q5 | 로그인 전에 올린 옛 글은 주인(`user_id`)이 비어 아무도 못 지운다 | 낮음 | SQL로 계정에 지정하거나 자동 삭제에 맡김 |
| Q6 | 영화관 약관이 예매 양도를 제한할 수 있다 (계획서 2-5) | 높음 | 3사 약관 확인, 정가 이하 등록 유지 |
| Q7 | 아이디 11자리는 번호 모양이라 본인 확인이 없다 (문자 인증 없음) | 중간 | 문자 인증 도입 시 비용·발송 업체 필요 |

## 10. 로드맵 (제안)
